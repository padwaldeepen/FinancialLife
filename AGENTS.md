# My Financial Life

Privacy-first personal finance app on localhost. One login per person, 1–3 sealed
single-currency **country profiles** (USA/India/Canada — never merged, no conversion).
Advises: monthly/annual breakdowns, recurring-bill detection, cash-flow forecast,
safe-to-spend, document (bill/receipt/statement) scanning with dedup.

**Read before working:** `docs/plan.md` (roadmap + definition of done) and
**`docs/backlog.md` (the ticket file — all implementation work comes from here: pick the
lowest open ticket whose dependencies are done, stay inside its scope, never invent
work)**. Reference specs: `docs/architecture-and-goals.md` (system + data model + AI
allocation), `docs/design-system.md` (3-color UI rules + page map).

## Tech Stack

- **Frontend**: React 19, TypeScript, Vite, CSS Modules, Radix UI Themes, Nivo charts
- **State**: Zustand slices (client + API data via slice actions)
- **Backend**: FastAPI (async), asyncpg (raw SQL, no ORM), Alembic (hand-written SQL
  migrations), PostgreSQL, JWT auth
- **AI tiers**: rules/statistics always; local tier C (pdfplumber text-layer +
  Tesseract OCR, zero network calls) is the default for document scanning; Gemini
  (cloud) is opt-in only, OFF by default, used for tougher documents/chat/insight
  rephrasing when the user's toggle is on. No Ollama — considered and dropped (see
  `services/ingest/document_extract.py`'s header comment for why); don't reintroduce
  it without a fresh decision.

## Project Structure

- `backend/` — FastAPI app (`core/`, `database/`, `routers/`, `services/`)
- `frontend/src/` — `desktop/` and `mobile/` (separate trees), `shared/`, `store/`, `styles/`
- `rules/` — coding rules (wired into opencode.json; apply in any tool)
- `docs/` — the four living docs above

## Key Conventions

- Routers are thin; business logic lives in `services/` (pure functions where possible)
- Every DB schema change ships with an Alembic migration
- **Raw SQL via asyncpg only — no ORM anywhere in application code** (see
  `rules/database.md`); Alembic remains the migration runner but migrations are
  hand-written SQL, not autogenerated from ORM models
- No pytest files anywhere — verify money math and every feature by driving the
  running app (curl + hand-computed fixtures for backend logic, Playwright against
  the live UI for features), not automated test files
- Every component: `Name.tsx` + `Name.module.css`; no Tailwind, no inline styles
- Colors: Radix tokens only, per `docs/design-system.md` (slate + orange + money
  green/red on amounts only — no other hues)
- Desktop = analyze/manage (full features + admin), mobile = capture/glance (trimmed);
  layouts never shared, logic/hooks always shared
- Cloud AI calls must stay behind the opt-in settings toggle

## Required After Every Change

1. Frontend: `npm run lint:fix && npm run format:fix` (from `frontend/`)
2. Backend: `ruff check . && ruff format .` (from `backend/`)
3. Verify live: curl + fixtures for backend logic, Playwright (both viewports) for
   any UI change — see "no pytest" above
4. Self-review the diff against `rules/code-review.md` before committing
   (in Claude Code: run the `/finance-review` skill, defined in `.claude/skills/`)

## Commands

- `docker compose up -d` — run everything
- `uvicorn main:app --reload` — backend dev (from `backend/`)
- `alembic upgrade head` — apply migrations. Migrations are **hand-written raw SQL**,
  never autogenerated — `alembic revision --autogenerate` is not used in this project
  (`alembic/env.py` sets `target_metadata = None` deliberately). Write a new revision
  by hand: `alembic revision -m "description"`, then fill in `UPGRADE_STATEMENTS`/
  `DOWNGRADE_STATEMENTS` yourself (see any file in `backend/database/alembic/versions/`
  for the pattern).
- `npm run dev` / `npm run build` — frontend (from `frontend/`)
